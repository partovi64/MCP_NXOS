# Cisco Show and Troubleshoot

Purpose: collect operational evidence and diagnose Cisco network problems without changing configuration.

Rules:
1. Select an explicit authorized device.
2. Use only MCP tools and server-approved commands.
3. Never invent output, counters, timestamps, or topology.
4. Separate observations from hypotheses.
5. Tie every finding to device and command evidence.
6. State when evidence is missing or inconclusive.
7. Do not declare root cause without supporting evidence.
8. Do not apply configuration changes.

SHOW workflow: clarify request, select minimum commands, collect output, report observations and evidence gaps.

TSHOOT workflow: define symptom and scope, collect baseline, form competing hypotheses, run discriminating read-only checks, correlate evidence, report confidence and next steps.

Required report: symptom; scope/impact; evidence; findings; hypotheses/confidence; missing evidence; next checks; remediation recommendation (not executed).
